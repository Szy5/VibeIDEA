# 需求设计文档

## 1. 项目概述

**项目名称**：科研日报 (Research Daily)  
**目标**：基于个人 Zotero 文献库与 arXiv 订阅，每日生成个性化论文推荐，并通过 Web 页面、邮件、微信公众号、飞书等多渠道展示与推送。

---

## 2. 功能需求

### 2.1 后端（推荐流水线）

| 编号 | 功能 | 说明 |
|------|------|------|
| R-B1 | Zotero 文献库拉取 | 从 Zotero 获取用户文献（会议/期刊/预印本），支持按集合过滤（gitignore 风格） |
| R-B2 | arXiv 论文检索 | 按配置的 RSS 查询获取当日新论文，支持 debug 模式（固定数量） |
| R-B3 | 论文重排序 | 基于 sentence-transformers 与 Zotero 摘要相似度 + 时间衰减进行 rerank |
| R-B4 | TLDR 生成 | 可选使用 OpenAI 或本地 LLM 生成论文一句话摘要 |
| R-B5 | Web 数据输出 | 将推荐结果写入 JSON（latest.json + 按日期），供前端展示 |
| R-B6 | 邮件推送 | 渲染 HTML 邮件并发送 |
| R-B7 | 微信公众号推送 | 渲染图文并创建草稿（含方法图提取与上传） |
| R-B8 | 飞书推送 | 渲染飞书消息并写入文件供外部发送 |

### 2.2 前端（Web 展示）

| 编号 | 功能 | 说明 |
|------|------|------|
| R-F1 | 每日 ArXiv 推荐页 | 从静态 JSON 拉取推荐列表，支持搜索过滤，展示标题、分类、摘要/TLDR、链接 |
| R-F2 | 科学发现图谱页 | D3 力导向图展示概念/方法/模型关系，支持搜索高亮与缩放 |
| R-F3 | 统一布局与导航 | 顶部导航、品牌区、全局样式与主题一致 |
| R-F4 | 无推荐数据时的提示 | 明确提示需先运行后端流水线生成数据 |

### 2.3 非功能需求

- **可维护性**：前后端目录与职责清晰，便于后续扩展（如增加 HTTP API）。
- **配置**：敏感信息与可调参数通过 `.env` / 环境变量管理，不写死在代码中。
- **运行方式**：后端为 CLI 流水线（可 cron 调度）；前端为静态资源 + 静态 JSON，无需常驻后端服务。

---

## 3. 数据流

```
Zotero API → 文献库
     ↓
arXiv RSS → 候选论文 → Rerank → [可选] LLM TLDR
     ↓
public/recommendations/latest.json (+ papers_YYYY-MM-DD.json)
     ↓
前端 fetch /recommendations/latest.json → 每日推荐页
```

---

## 4. 约束与假设

- 前端仅消费**静态 JSON**，不依赖实时 HTTP API。
- 图谱页当前使用**静态示例数据**，与推荐流水线独立。
- 后端需在能访问 Zotero/arXiv/OpenAI（若启用）的网络环境下运行。
