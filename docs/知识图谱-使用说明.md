# 知识图谱构建 - 使用说明

本文说明如何在本地（含 conda 环境、代理与 GPU）运行知识图谱构建脚本，并查看结果。

---

## 1. 环境准备

### 1.1 Conda 环境

请在 **conda 环境 `research`** 下运行构建脚本：

```bash
conda activate research
```

确保该环境中已安装项目依赖（见下节）。

### 1.2 安装依赖

在项目根目录下执行：

```bash
pip install -r requirements.txt
```

如需使用 **FAISS 标题相似度融合**（默认开启），`requirements.txt` 中已包含 `faiss-cpu`。若本机有 GPU 且希望用 GPU 版 FAISS，可自行安装：

```bash
pip install faiss-gpu
```

（脚本中编码器 `allenai-specter` 会优先使用 GPU，FAISS 索引检索使用 CPU 即可。）

### 1.3 代理配置（下载模型必备）

首次运行且启用 FAISS 时，会从 Hugging Face 下载 **allenai-specter** 模型。若网络受限，需配置代理，否则容易下载失败。

在项目根目录的 **`.env`** 中增加（请改成你自己的代理地址和端口）：

```ini
HTTP_PROXY=http://127.0.0.1:7890
HTTPS_PROXY=http://127.0.0.1:7890
```

或在当前 shell 中设置环境变量后再运行脚本：

```bash
set HTTP_PROXY=http://127.0.0.1:7890
set HTTPS_PROXY=http://127.0.0.1:7890
python -m backend.build_knowledge_graph --full
```

脚本在**程序入口**会加载 `.env`，使 `HTTP_PROXY` / `HTTPS_PROXY` 在下载模型前生效。

---

## 2. 运行方式

在项目根目录下执行（请先 `conda activate research`）。

### 2.1 全量重建（首次或清空后重算）

```bash
python -m backend.build_knowledge_graph --full
```

- 会读取 `results/` 下所有 `prior_work_analysis_*.json`。
- 若启用 FAISS，会加载或新建 FAISS 索引，并用 **GPU**（若可用）跑标题编码；首次会下载 `allenai-specter`，需保证代理可用。
- 输出：`public/graph/papers_kg.json`、`papers_kg_index.json`，以及（启用 FAISS 时）`papers_kg_faiss.index`、`papers_kg_faiss_ids.json`。

### 2.2 增量更新（仅处理新增/更新的分析文件）

```bash
python -m backend.build_knowledge_graph
```

- 根据 `papers_kg_index.json` 判断哪些分析文件为新增或已更新，只处理这些文件并合并到已有图与 FAISS 索引。

### 2.3 常用可选参数

| 参数 | 说明 |
|------|------|
| `--full` | 全量重建，忽略已有图和索引 |
| `--no-faiss` | 关闭 FAISS 标题相似度融合，仅用 arxiv_id + 标题完全匹配 |
| `--faiss-threshold T` | FAISS 余弦相似度阈值，默认 0.88，可试 0.85～0.92 |
| `--cpu` | 标题编码强制使用 CPU（默认：有 GPU 则用 GPU） |

示例：

```bash
# 全量重建，且 FAISS 相似度阈值设为 0.90
python -m backend.build_knowledge_graph --full --faiss-threshold 0.98

# 仅用 arxiv + 标题匹配，不下载模型、不用 GPU
python -m backend.build_knowledge_graph --full --no-faiss

# 全量重建但编码用 CPU
python -m backend.build_knowledge_graph --full --cpu
```

## 3. 输出文件说明

| 文件 | 说明 |
|------|------|
| `public/graph/papers_kg.json` | 图数据（nodes + edges），前端直接读取 |
| `public/graph/papers_kg_index.json` | 已处理分析文件及时间戳，用于增量 |
| `public/graph/papers_kg_faiss.index` | FAISS 索引（启用 FAISS 时生成） |
| `public/graph/papers_kg_faiss_ids.json` | FAISS 向量对应的节点 id 列表 |

## 4. 融合日志

运行时会打印融合日志，便于排查和调参：

- `[FUSION] title: "..." -> node_id=xxx`：按标题完全一致（忽略大小写）合并。
- `[FUSION] arxiv: "..." -> node_id=xxx`：按 arxiv_id 合并。
- `[FUSION] faiss score=0.xxxx: "..." -> node_id=xxx`：按 FAISS 标题相似度合并，并带相似度分数。

若发现本应合并的论文未合并，可适当**调低** `--faiss-threshold`（如 0.85）；若误合并增多，可**调高**（如 0.90～0.92）。

## 5. 测试验证

交付前建议按下列步骤自测：

1. **无 FAISS 全量构建（不依赖网络）**  
   在项目根目录、conda 环境 `research` 下执行：
   ```bash
   conda activate research
   python -m backend.build_knowledge_graph --full --no-faiss
   ```
   应正常结束并打印 `[KG] Done. Nodes=..., Edges=...`。

2. **输出校验**  
   确认 `public/graph/papers_kg.json` 存在且为合法 JSON，包含 `nodes`、`edges` 数组；`public/graph/papers_kg_index.json` 包含 `papers` 等字段。

3. **带 FAISS 全量构建（需代理）**  
   配置好 `.env` 中的 `HTTP_PROXY`/`HTTPS_PROXY` 后执行：
   ```bash
   python -m backend.build_knowledge_graph --full
   ```
   首次会下载 allenai-specter，完成后会多出 `papers_kg_faiss.index`、`papers_kg_faiss_ids.json`，控制台可能出现 `[FUSION] faiss score=...` 的融合日志。

## 6. 常见问题

- **模型下载失败**  
  确认已配置代理（`.env` 中 `HTTP_PROXY`/`HTTPS_PROXY` 或当前 shell 环境变量），并在 **conda 环境 research** 下运行；脚本会在入口处加载 `.env`。

- **CUDA/GPU 不可用**  
  脚本会自动回退到 CPU 编码；也可显式加 `--cpu`。

- **不想用 FAISS**  
  加 `--no-faiss`，不会下载 `allenai-specter`，也不依赖 GPU。

- **数据与前端**  
  构建完成后，前端「科学发现图谱」页会从 `public/graph/papers_kg.json` 拉取图数据并展示；若未看到更新，可检查该文件是否已更新并刷新页面。
