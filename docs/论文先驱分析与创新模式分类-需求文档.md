# 论文先驱分析与创新模式分类需求文档

## 1. 项目概述

**目标**：针对已经从 ACL / AAAI 推荐出的论文集合，构建一条两阶段分析流水线：

1. 批量下载论文 PDF，并抽取每篇论文的关键先驱工作（prior works）与综合叙述（synthesis narrative）。
2. 基于综合叙述进一步识别论文的创新模式（innovation / thinking pattern classification）。

该能力面向当前项目中的推荐结果数据，服务于后续的：

- 结构化科研分析
- 创新模式统计
- 知识图谱构建
- 人工复核与后续研究辅助

---

## 2. 功能需求

### 2.1 阶段一：先驱工作抽取

| 编号 | 功能 | 说明 |
|------|------|------|
| R-P1 | 读取推荐论文 JSONL | 从本地推荐结果读取论文标题、摘要、作者、会议、年份、URL 等元信息 |
| R-P2 | 官方 PDF 下载 | 优先从论文官方来源下载 PDF，并保存到本地 `raw_paper/pdfs` |
| R-P3 | PDF 文本抽取 | 从 PDF 中提取正文文本，供大模型分析 |
| R-P4 | 关键先驱工作识别 | 使用与 Sci-Reasoning 一致的 prior-work extraction 逻辑，识别 5-7 篇直接影响当前论文核心创新的先前工作 |
| R-P5 | 综合叙述生成 | 生成 `synthesis_narrative`，描述这些 prior works 如何共同导向当前工作 |
| R-P6 | 结构化结果输出 | 为每篇论文输出 JSON 与 Markdown 两份结果 |
| R-P7 | 断点续跑 | 已完成样本跳过，失败样本在再次运行时继续补跑 |

### 2.2 阶段二：创新模式分类

| 编号 | 功能 | 说明 |
|------|------|------|
| R-C1 | 读取 prior work JSON | 从阶段一输出的 `prior_work_analysis_*.json` 中读取 `synthesis_narrative` |
| R-C2 | 加载模式 taxonomy | 使用 Sci-Reasoning 的 thinking-pattern taxonomy |
| R-C3 | 批量模式分类 | 批量调用大模型，根据 narrative 为论文打上主创新模式与次创新模式标签 |
| R-C4 | 分类结果回写 | 将 `innovation_classification` 写回原始 JSON |
| R-C5 | checkpoint 续跑 | 支持中断后从 checkpoint 恢复，不重复分类已完成论文 |
| R-C6 | 分类汇总输出 | 输出分类 summary / cost / checkpoint 文件，便于后续统计与审计 |

### 2.3 元信息校准

| 编号 | 功能 | 说明 |
|------|------|------|
| R-M1 | 目标论文标题校准 | 尽可能基于 OpenAlex / Crossref / arXiv 修正 `paper_title` |
| R-M2 | prior works 标题校准 | 对模型生成的先前工作标题进行标准化 |
| R-M3 | arXiv ID 回填 | 在置信度足够时，为 prior work 或目标论文补充 arXiv ID |
| R-M4 | 变更日志记录 | 记录处理前后标题与 arXiv ID 的变化，支持人工复核 |

### 2.4 非功能需求

- **兼容 Sci-Reasoning**：prior-work extraction 目标与核心 prompt 应保持一致，不随意改写任务定义。
- **可恢复性**：长任务必须支持断点续跑。
- **可观测性**：批处理阶段必须有实时日志，能够看到当前进度与失败样本。
- **可复核性**：所有自动修正与分类结果需要有结构化日志或汇总文件，方便人工抽查。
- **低侵入性**：新增能力不应破坏原有推荐流程与已有输出结果。

## 3. 输入输出要求

### 3.1 输入

1. 推荐论文 JSONL：

- `raw_paper/recommended_acl_aaai_top300_min7.65.jsonl`

2. 本地 PDF 存储目录：

- `raw_paper/pdfs`

3. prior work 结果目录：

- `results/recommended_acl_aaai_top300_min7.65_prior_work`

4. 模式 taxonomy：

- 来自 Sci-Reasoning 的 `pattern_taxonomy.json`

### 3.2 输出

#### 阶段一输出

- `prior_work_analysis_*.json`
- `prior_work_analysis_*.md`
- `manifest.json`
- `*_download_manifest.json`

#### 阶段二输出

- 回写后的 `prior_work_analysis_*.json`
- `thinking_pattern_classification_checkpoint.json`
- `thinking_pattern_classification_summary.json`
- 分类运行日志

#### 元信息校准输出

- enriched JSON 目录或原地覆盖结果
- `enrichment_log.jsonl`

## 4. 业务约束与假设

- 推荐论文来源当前主要为 ACL / AAAI，URL 可能不是 arXiv。
- 一部分论文没有 DOI，也没有 arXiv ID，因此标题与 ID 校准只能做到部分覆盖。
- `innovation_classification` 不是 prior-work 抽取阶段的天然输出，而是基于 `synthesis_narrative` 的第二阶段分类结果。
- 批处理过程可能持续较长时间，需要面向中断、重启和 API 抖动设计。

---

## 5. 典型流程

### 5.1 标准流程

```text
推荐 JSONL
  -> 下载 PDF
  -> 抽取 PDF 文本
  -> GPT prior-work extraction
  -> 生成 prior_work_analysis_*.json / *.md
  -> thinking pattern classification
  -> 回写 innovation_classification
  -> 元信息校准（可选）
```

### 5.2 恢复流程

```text
任务中断
  -> 再次执行相同命令
  -> 已完成样本自动跳过
  -> 未完成样本继续处理
  -> thinking pattern 分类从 checkpoint 恢复
```

---

## 6. 成功标准

满足以下条件即视为功能完成：

1. 能够从推荐 JSONL 批量生成 prior-work JSON 与 Markdown。
2. 能够在再次运行时跳过已完成样本，仅补跑缺失结果。
3. 能够基于 `synthesis_narrative` 生成 `innovation_classification` 并写回 JSON。
4. 能够输出处理日志、checkpoint、summary、修正日志等辅助文件。
5. 对于标题与 arXiv ID 校准，自动更新必须是保守且可审计的。
